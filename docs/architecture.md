# 構成と実装方針

## 採用した構成

利用者の指定により実装言語をGoとし、Windows 11・PowerShellで利用する単一の実行ファイルを作ります。最低対応版は[go.mod](../go.mod)、操作と検証の入口は[README](../README.md)を参照してください。公開先は未指定のため、モジュール名はローカル開発用の`rulecheck`とします。

`cmd/rulecheck/main.go`がプロセスの入出力と終了を担い、`internal/cli`が引数処理・使い方・版番号・検査結果の表示を扱います。`internal/report`が結果型・分類別件数・状態・終了コードを定め、`internal/scan`がファイルと共有リンク、Markdown参照、スキルの列挙・YAMLメタデータ・名前、CLI候補の検索を実装しています。CLI版番号は`internal/version/version.go`から参照します。構文解析にはgoldmarkとgo-yamlを使い、選定と固定版は[依存関係](dependencies.md)へ記録しています。

検査本体は、次の順序でデータを扱う設計とします。必要な処理を実装するときにパッケージを分け、先に空の層を作りません。

1. 引数から明示された検査対象だけを確定する。
2. ファイルの種類・リンク先・実体を解決し、別名と同じ実体を対応付ける。
3. 許可された指示ファイルと直下の`SKILL.md`の構造を解析し、参照先は存在と種類だけを調べる。
4. 明示されたCLI名の候補だけを現在の`PATH`から探す。
5. 分類した結果を安定した順序でまとめ、通常表示またはJSONと終了コードへ変換する。

検査範囲、結果の分類、終了コード、JSONに必要な項目は[要件定義書](requirements.md)を正本とします。

## 読み取り専用の境界

| 対象 | 許可する処理 | 制約 |
| --- | --- | --- |
| 明示された指示ファイルと直下のスキル | 種類・リンク先・実体の確認、本文の読み取り | 個人設定全体や入れ子のスキルを暗黙に走査しない |
| 本文中のローカル参照 | パスの解決、存在と種類の確認 | リンク先の本文を再帰的に読まない |
| YAMLのメタデータ | 構造と必要な項目の型を確認 | 値をそのまま診断へ転載しない |
| `--command`で明示された名前 | `PATH`から実行ファイル候補を探す | 実行、導入、認証を行わない |
| 外部URLと本文の指示 | 検査対象外として分類 | ネットワーク接続や指示・コマンドの実行を行わない |

相対参照は、記述元ファイルの実体があるディレクトリを基準にします。別名のパスを基準にせず、同じ実体から得た結果が変わらないようにします。パス解決時の不在と権限不足を区別し、判定不能を成功扱いにしません。実行時は対象・設定・キャッシュ・ロックを作成しません。

M2では、明示されたファイルと直下の`SKILL.md`だけを読み取ります。通常ファイル以外は本文を開かず、UTF-8として不正な本文やNULを含む本文は判定不能とします。リンクの各構成要素を`os.Lstat`・`os.Readlink`で確認し、循環と255回を超える解決を区別します。Windowsではジャンクションの再解析ポイント属性も確認します。同一実体は`os.SameFile`で判定し、本文の一致から推測しません。[Goのosパッケージ](https://pkg.go.dev/os@go1.27.3)を参照しています。

未対応のWindows再解析ポイントでは、`os.Readlink`が不存在に相当するエラーを返す場合も、読取不能として判定します。直下の`SKILL.md`の列挙でもこの分類を使い、単なる不存在だけを補助ディレクトリとして除外します。実際の模擬タグを使った確認は[受入確認](acceptance.md)へ記録します。

UNCとデバイスパス、代替データストリームはメタデータを読む前に拒否します。ドライブ文字のパスも[WindowsのGetDriveTypeW](https://learn.microsoft.com/ja-jp/windows/win32/api/fileapi/nf-fileapi-getdrivetypew)で種別を確認し、ネットワーク・不明なドライブは開きません。実際のネットワークドライブへの割当や接続は検証では行っていません。種別の判定境界をテストし、通常のローカルドライブで受入確認しています。

## MarkdownとYAMLの解析

同一実体の集約と実体パスの確定後、本文を一度読み取ります。ハードリンクで実体パスが複数ある場合も、選ばれた昇順先頭の実体ディレクトリを基準にします。UTF-8のBOMは除去し、CRLFにも対応します。

MarkdownはgoldmarkのCommonMark解析器で構文木を作り、通常・参照形式・画像のリンクを取り出します。コードブロックとインラインコードは対象外の診断へ変換し、その中を参照として解析しません。Markdownのエスケープ・文字参照を解き、見出しの断片を切り離してからパーセント符号化を一度だけ解きます。参照先は既存のローカル専用の解決へ渡し、通常ファイルまたはディレクトリであることを確認します。本文は開きません。成功した参照ごとの診断は増やさず、見出しの検査を省略した場合は対象外として残します。

外部URIは値を転載せず対象外とします。`file:` URI、ドライブ基準の相対パス、問い合わせ文字列、不正な符号化、ネットワーク上の参照は判定不能です。未定義の参照形式・二重角括弧などは、構文木中の本文を装飾をまたいで確認し、リンクに似た記述を解釈できなかった旨を残します。成立済みリンクやコードの内容から独自参照を推測しません。HTMLの参照属性（`href`・`src`・`cite`・`formaction`など）と`url(...)`は未対応として残し、コメントと参照を持たないHTMLは参照検査に混ぜません。HTML・独自記法全体を検証するものではありません。

スキルの先頭メタデータは単独行の`---`で囲まれた範囲です。go-yamlで構文木を取得し、対応表・重複キー・不正な別名や循環・複数文書を確認します。`name`と`description`は、文字列への自動変換を使わず節点の型と空白を除いた長さを検査します。別名とマージも型を保って解決します。不正な構文について解析器のエラー文を転載せず、固定した日本語の診断を返します。メタデータ部分を空白へ置き換えてMarkdown解析から除き、元の本文行番号を保ちます。終端がなく本文の開始位置を確定できない場合は、参照検査も判定不能にします。

有効なスキル名は内部でのみ照合し、値そのものを出力しません。実体ディレクトリ名との差異と、集約済みの異なる実体間での重複を注意へ変換します。重複の診断には関係する実体パスを残します。

## CLI候補の検索

現在の`PATH`だけを指定順に調べ、通常ファイルの候補が1つ見つかれば存在確認を完了します。Windowsの拡張子は`PATHEXT`の順序を使い、空の場合は`.COM;.EXE;.BAT;.CMD`を使います。拡張子を含む名前は、その名前自体も先に調べます。この扱いは[GoのWindows向け候補検索](https://go.dev/src/os/exec/lp_windows.go)を参照しました。候補の実行は行わないため、ファイルの実行可能性や起動時に実際に選ばれるコマンドまでは保証しません。

`os/exec.LookPath`へ検索を任せると、ネットワーク上の`PATH`やリンク先を存在確認時に開く可能性があります。このため、既存のローカル専用のパス解決を使い、候補本文を開かずに種類と実体だけを確認します。暗黙の作業ディレクトリ検索は追加しません。`PATH`に明記された相対ディレクトリは解決し、空の要素は無視します。拡張子設定に区切り文字や特殊なパスを組み立てる値があれば、その設定を使わず判定不能の要因として残します。

確認できる候補がなく、検索先にネットワーク上のパス・権限不足・解決回数の上限などが残れば`command_unresolved`とします。検索できた範囲で不在、ディレクトリ、リンク切れ・循環しかない場合は`command_missing`とします。別のローカルの検索先で候補を確認できれば、候補の存在という判定は完了しています。PowerShellの関数・エイリアス、本文中のコードからのCLI名抽出は行いません。

## 結果の形式

JSON形式の版番号の正本は`internal/report/report.go`の`SchemaVersion`です。初回は`1`とし、次の項目をJSONオブジェクト1件として出力します。

| 項目 | 現在の実装 |
| --- | --- |
| `schema_version` | JSON形式の版番号 |
| `tool` | `name`は`rulecheck`、`version`はCLI版番号の正本から取得 |
| `command` | `scan` |
| `status` | 分類別件数から決定する状態。不正引数の場合は`invalid_arguments` |
| `coverage` | `rules`・`references`・`skills`・`commands`の検査範囲ごとの実施状況 |
| `results` | 対象の`kind`・`target`、ファイル系の`aliases`・`resolved_path`・`links`、その対象の`findings` |
| `counts` | 診断の分類別件数。対象数ではなく、`findings`の件数を集計 |

`coverage`は、指示ファイルと共有リンクを`rules`、Markdown参照を`references`、直下のスキルの列挙と基本項目を`skills`、CLI候補検索を`commands`で表します。未指定は`not_requested`、未実装は`not_implemented`、引数誤りで開始しなかった場合は`not_run`です。実施済みの検査は`completed`、一部だけ実施または判定不能がある検査は`partial`です。エラーを確定できた場合も、その項目の判定自体は実施済みです。指示ファイルかスキルが指定されると、Markdown参照の検査も必要とします。

対象の`kind`は`rules`・`skills`・`skill`・`command`です。`skills`は指定した親、`skill`は直下で見つかった`SKILL.md`または解決に失敗した子リンクを表します。不正引数の結果に限り`arguments`とし、`target`を空文字列にします。ファイル系の`target`はまとめた指定のうち文字列の昇順で最初のものとし、`aliases`に指定された別名を残します。`resolved_path`はリンク解決後の絶対パスです。ハードリンクで複数ある場合は昇順で最初の実体パスを選びます。CLIでは最初に確認できた候補の実体パスを`resolved_path`へ入れます。`links`は通過したリンクの`path`と、そこに記録された`target`の組です。解決に失敗した実体パスや、空のリンク配列は省略します。

`findings`の各診断は`code`・`category`・`message`・`source`・`paths`を持ち、行番号が分かる場合だけ`line`を含めます。記述元は解決できた実体パス、解決できなければ指定パスとし、親ディレクトリやCLIの診断では空文字列にします。関係するパスがなければ`paths`は空配列です。本文やYAMLの値、不正な引数の値は診断へ転載しません。

対象は`kind`・`target`の順、診断は`source`・`line`・`code`・`category`・`message`・`paths`の順に並べます。関係するパスと別名は文字列の昇順、リンクは`path`・`target`の順に並べ、重複を除きます。同じ種類の同一実体は1件にまとめます。スキルの親の別名は、子の`SKILL.md`の別名にも引き継ぎます。

固定した`code`は次のとおりです。

| 分類 | code |
| --- | --- |
| 引数誤り | `invalid_arguments` |
| エラー | `path_missing`・`path_not_file`・`path_not_directory`・`link_broken`・`link_cycle`・`command_missing` |
| 判定不能 | `path_unreadable`・`directory_unreadable`・`text_unsupported`・`path_not_local`・`link_limit`・`command_unresolved` |
| 参照のエラー | `reference_missing`・`reference_link_broken`・`reference_link_cycle` |
| 参照の判定不能 | `reference_unsupported`・`reference_unresolved`・`reference_unreadable`・`reference_not_local`・`reference_not_regular`・`reference_link_limit` |
| メタデータのエラー | `metadata_missing`・`metadata_invalid`・`metadata_name_missing`・`metadata_name_invalid`・`metadata_description_missing`・`metadata_description_invalid` |
| スキル名の注意 | `skill_name_duplicate`・`skill_name_mismatch` |
| 参照の対象外 | `reference_external_skipped`・`reference_fragment_skipped`・`reference_code_skipped` |

分類別件数と状態・終了コードは共通の結果型で決定し、通常表示とJSONで共用します。参照だけの判定不能は`coverage.references`へ反映し、指示ファイル自体の存在・読取確認まで未完了にしません。元ファイルを読めなかった場合や親ディレクトリを列挙できなかった場合は、参照検査も`partial`です。不在や不正なメタデータなど確定したエラーは、未実装の診断を追加せず終了コード`1`になります。参照の関係パスは元ファイルの別名で上書きしません。通常表示にも記述位置と関係パスを表示します。出力に失敗した場合は標準エラーへ日本語の診断を出し、終了コード`2`を返します。ただし引数誤りでは`64`を維持します。

## 後続実装で決める事項

- 製品全体の受入確認はM4で結果と要件の対応を確定します。未対応の参照を検査済みとして扱わない境界も継続して確認します。
- 初期のローカル成果物は`bin/rulecheck.exe`です。外部の公開先、配布経路、ライセンスは未決定で、初期設定では追加しません。
