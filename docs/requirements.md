# rulecheck 要件定義書

- 文書版: 1.0
- 状態: 初版・未実装
- 目的: LLM向けの指示ファイルとスキルについて、参照先・共有リンク・必要なCLIの存在を読み取り専用で検査する。

## 1. 利用場面と完成条件

AGENTS.md、GEMINI.md、個人用スキルを更新した後に使う。ファイル間の参照切れ、壊れた共有リンク、スキルの基本項目の欠落、明示したCLIの不足を一括して把握できることを完成条件とする。

例えばGEMINI.mdがAGENTS.mdを指す共有リンクである場合、参照先と同じ内容を読めることを確認する。同じ実体への別名を、重複したスキルや矛盾した指示として扱わない。

検査するのは指定されたファイルの構造と存在関係である。LLMが実際に読んだ内容、各製品の指示の読み込み順序、自然文の意味の矛盾、実行権限や認証の有効性は保証しない。

## 2. 初版の対象

- Windows 11・PowerShellで利用する非対話型CLIとする。
- 検査する指示ファイルとスキルの親ディレクトリは、コマンドの引数で明示する。
- 個人用の設定ディレクトリ全体や、すべてのMarkdownを暗黙に走査しない。
- 各スキルの本文、指示ファイルの本文、参照先をデータとして読み、書かれたコマンドや指示を実行しない。
- 自動修正、リンクの作成・同期、スキルのインストール、外部URLの検査、指示の意味の採点は初版に含めない。
- 他の3つのCLIに依存せず、単独で利用できるものとする。

## 3. コマンド

| コマンド | 要件 |
|---|---|
| rulecheck scan [--rules <ファイル> ...] [--skills <親ディレクトリ> ...] [--command <名前> ...] [--json] [--summary] | 明示した対象を検査する。対象を少なくとも1つ指定する。 |
| rulecheck --help / --version | 日本語の使い方、検査範囲、版番号を表示する。 |

使用例:

    rulecheck scan --rules C:/Users/shouh/.codex/AGENTS.md --rules C:/Users/shouh/.gemini/GEMINI.md --skills C:/Users/shouh/.agents/skills --command rg --command sd --command htmlq --command lychee --json

これらのパスとコマンドは例であり、利用者名やホームディレクトリを実装へ固定しない。相対パスは実行時の作業ディレクトリを基準にする。

--skills では、指定した親ディレクトリの直下にある各スキルディレクトリの SKILL.md を検査する。評価事例や同梱ソース内の入れ子の SKILL.md は自動走査しない。SKILL.mdを持たない補助ディレクトリはスキルとみなさない。

## 4. 検査項目

### 4.1 指示ファイルと共有リンク

- 指定されたファイルが存在し、通常のテキストとして読めることを確認する。
- シンボリックリンクの参照先と実体を示し、リンク切れ、循環、参照先の読取不能を検出する。
- 同じ実体への複数の指定をまとめつつ、指定された別名と参照関係は出力に残す。
- 別々の通常ファイルであるというだけで、内容の違いをエラーと判定しない。製品別の指示として正当な場合があるため、意味の一致や同期の必要性は自動判定しない。

### 4.2 Markdown内のローカル参照

- 通常のリンク、参照形式のリンク、画像のローカル参照について、参照先の存在と種類を確認する。
- コードブロックやインラインコード中の例を、実際の参照として扱わない。
- 相対参照は、記述元のファイルの実体があるディレクトリを基準に解決する。この基準は各LLM製品の実際の読み込み処理を再現するものではない。
- #だけの参照、http・https・mailtoなど外部の参照は対象外とする。ローカルパスに付く見出しの断片は、ファイルの存在確認から取り除き、見出し自体は検査しない。
- リンク先の本文を再帰的に読まない。空白、日本語、エスケープ、Windowsの絶対パスを扱い、解釈できない参照は理由を示す。
- 任意のコード記法からファイル名を推測しない。初版で対応しない独自記法を、検査済みと表示しない。

### 4.3 スキルの基本項目

- SKILL.md先頭のYAML形式のメタデータが解釈でき、name と description が空ではない文字列であることを確認する。
- 不明な追加項目があるというだけでエラーにしない。
- 異なる実体のスキルでnameが重複している場合と、スキルのディレクトリ名とnameが異なる場合は注意として報告する。
- 同じ実体を複数の共有リンクから見た場合は、重複したnameの注意を出さない。
- この基本検査を、特定製品のスキル仕様すべてへの準拠確認や、スキルの実行品質の評価とは扱わない。

### 4.4 必要なCLI

- --command で明示された名前について、現在のPATHから実行ファイルの候補が見つかるか調べる。
- Markdown中のバッククォート内の語を、すべてCLI名として抽出しない。設定キー、識別子、サンプルを必要なCLIと誤認しない。
- CLI本体は実行せず、導入、認証、実行ポリシー、サンドボックス内の動作を保証しない。PowerShellの関数・エイリアスは初版の対象外とする。

## 5. 結果の分類と出力

| 分類 | 例 |
|---|---|
| error | 指定ファイルの不存在、リンク切れ・循環、存在しないローカル参照、必須メタデータの欠落、明示したCLIの不足。 |
| warning | 異なる実体でのスキル名の重複、ディレクトリ名とnameの差異。 |
| unknown | 読取権限不足、未対応の参照形式、検査処理の失敗など、必要な判定ができなかったもの。 |
| skipped | 外部URL、見出しの断片、コード中の例など、仕様上検査しないもの。 |

通常表示は日本語の簡潔な結果とする。--json では標準出力にJSONオブジェクト1件を出し、進捗や内部診断は標準エラーに分ける。

--summary では、通常表示とJSONのいずれも skipped の個別診断を出さず、全対象を通じた code 別の件数にまとめる。error・warning・unknown の詳細、対象の識別情報、検査範囲、総件数、状態・終了コードは変えない。詳細が必要な場合は --summary を外して同じ検査を実行する。既定では従来どおり skipped の詳細を含める。

JSONには schema_version、tool、command、status、coverage、対象別の results、分類別の件数を含める。status は passed / warning / failed / incomplete / invalid_arguments とする。

各結果には機械判定用の code、分類、日本語の説明、記述元ファイル、分かる場合の行番号、関係するパスを含める。ファイル本文やYAMLの値を、そのままエラーメッセージへ転載しない。配列の並び順とcodeは同一条件で安定させる。

## 6. 終了コードと副作用

| 終了コード | 意味 |
|---|---|
| 0 | 検査完了、error・unknownなし。warningのみの場合も0とする。 |
| 1 | errorあり。 |
| 2 | unknownあり、または必要な検査を完了できない。errorが併存しても2を優先する。 |
| 64 | 引数の誤り。 |

warning・skippedの有無と対象は、終了コード0でも出力に残す。--summary の skipped は種類別件数とし、個別の記述位置や関係するパスは省く。ネットワークへ接続せず、ファイル、リンク、設定、キャッシュ、ロックを作成・変更しない。

## 7. 受入条件

1. 指示ファイルを共有する正常なリンクを解決し、実体の別名として報告する。
2. リンク切れ、循環、読取不能を区別し、検査成功と誤認しない。
3. 通常・参照形式・画像のローカルリンクを確認し、コード中の例や外部URLを検査対象に混ぜない。
4. 相対参照の基準が共有リンクの別名によって変わらず、空白・日本語のあるパスを扱う。
5. 不正なメタデータ、name・descriptionの欠落や型の誤りを検出する。
6. 異なる実体の同名スキルには注意を出し、同じ実体への別名には同じ注意を出さない。
7. 明示したCLIの不足を検出し、コード例中の単語を未導入CLIとして誤検出しない。
8. 壊れた参照先の本文や機密情報、埋め込まれた指示を読取・実行しない。対象CLIも起動しない。
9. JSON、分類、件数、終了コードが一致し、検査前後に対象ファイルや設定が変化しない。
10. --summary では skipped の総件数と種類別件数が一致し、個別診断を出さずにほかの分類の詳細と判定を保持する。指定を外すと skipped の詳細を取得できる。

実装時には模擬の指示・スキル・リンクを一時ディレクトリに作って確認する。Windowsでリンクを作成できない環境では、その検証を未確認とし、成功扱いにしない。

## 8. 版管理と実装時に決める事項

本書の初版は1.0とする。CLIは未実装のため、今回のCLI版番号の更新は対象外。実装開始時の初回CLI版は0.1.0、JSON形式は schema_version: 1 とし、版番号の正本を1か所に定めて --version と配布物を一致させる。

実装言語、配布方法、Markdown・YAMLを解析する方式は実装時に決める。初版は明示された範囲の構造検査を完成させる。各製品の読み込み順序の再現や自然文の意味の検査を追加する場合は、別の要件として範囲と根拠を定める。
