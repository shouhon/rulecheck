# 開発計画

## 目標と参照先

[要件定義書](requirements.md)の受入条件を満たす、Windows用の読み取り専用CLIを完成させます。[構成と実装方針](architecture.md)を設計の参照先、[README](../README.md)を開発と検証の入口とします。

開発基盤の初期設定を終え、検査機能を順に実装します。この文書で工程と未完了範囲を管理します。

## リスクと未決定事項

| 項目 | 影響 | 対応 |
| --- | --- | --- |
| Windowsのリンク作成権限とリンクの種類 | 通常ファイルだけの検証では共有リンクの受入条件を満たせない | M2とM4で実機確認し、作成不可の確認項目は未確認と記録する |
| Markdown・YAMLの解析方式 | 簡易な解析ではコード除外、エスケープ、型の判定を誤るおそれがある | M3で必要な構文を比較し、外部依存が必要なら根拠と固定する版を記録する |
| 機密値の出力と対象CLIの実行 | 読み取り専用という前提を壊す | 模擬の秘密値・埋め込み指示・実行痕跡を残す模擬CLIで、外から観測できる検証を行う |
| 公開先・配布経路・ライセンス | 配布条件とモジュールの公開用識別子が未確定 | ローカルビルドまでとし、公開・署名・配布を開始する前に決める |

## 現在地

- 完了: M0〜M2と、M3のCLI候補検索。現在の`PATH`とWindowsの`PATHEXT`から明示した名前の候補を確認し、不足と判定不能を区別する。MarkdownとYAMLの解析は未実装として残している。
- 実装時の検証: Go 1.27.3・Windows/amd64、`GOCACHE=.cache/go-build`で必須の書式・モジュール整合性・静的検査・テスト・ビルド・起動が成功した。追加したテストで、PATHと拡張子の順序・既定値・明示した拡張子、空白・日本語・相対PATH、作業ディレクトリの暗黙検索の除外、ディレクトリの除外、候補のリンク解決、外部のPATH・リンク先と不正な拡張子設定の判定不能を確認した。Windowsの共有を拒むファイルハンドルで、候補本文を読まず存在確認できることも確認した。関連テストの詳細実行でリンク作成不可によるスキップはなかった。
- CLI候補検索の受入確認: ビルドした実行ファイルを一時ディレクトリ内の模擬データで動かし、候補あり・不足・判定不能、通常表示・JSON・分類別件数・終了コード`0`・`1`・`2`、指定順と再指定に依存しない出力を確認した。本文のコード例をCLIとして抽出せず、指示ファイルの参照検査が未実装であることも残る。模擬CLIの起動痕跡と模擬秘密値の出力はなく、対象のSHA-256、更新日時、属性、ディレクトリ構成は前後で一致した。実装時の自己検証と実行ファイルでの受入確認を分けた。変更文書のローカルリンクも`lychee --offline`でエラーなし。
- 独立確認: 読み取り専用の補助担当が差分を確認し、未対応のWindows再解析ポイントで`Readlink`が不存在を返した場合、確認不能をCLI不足と誤認する箇所を指摘した。PATH要素と候補の両方で既存の`pathFinding`の分類を共用し、主担当が既存の回帰テストを確認して必須検証を再実行した。補助担当も修正後の指摘解消を静的に確認した。実際の未対応再解析ポイントでの再現とネットワーク通信の監視は未実施で、独立確認は実行確認ではない。
- 検証対象: 基準コミット`5fdefa9`にCLI候補検索を加えたCLI版`0.1.0`。受入確認した実行ファイルのSHA-256は`0295917be93a776c4d6737f672489f964cd480e11453932b612a3f1d8c7bb6ed`。正本と`bin/rulecheck.exe --version`の一致を確認した。
