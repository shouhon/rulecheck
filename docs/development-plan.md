# 開発計画

## 目標と参照先

[要件定義書](requirements.md)の受入条件を満たす、Windows用の読み取り専用CLIを完成させます。[構成と実装方針](architecture.md)を設計の参照先、[README](../README.md)を開発と検証の入口とします。

開発基盤の初期設定を終え、検査機能を順に実装します。この文書で工程と未完了範囲を管理します。

## リスクと未決定事項

| 項目 | 影響 | 対応 |
| --- | --- | --- |
| Windowsのリンク作成権限とリンクの種類 | 通常ファイルだけの検証では共有リンクの受入条件を満たせない | M2とM4で実機確認し、作成不可の確認項目は未確認と記録する |
| Markdown・YAMLの解析方式 | 簡易な解析ではコード除外、エスケープ、型の判定を誤るおそれがある | M3で必要な構文を比較し、外部依存が必要なら根拠と固定する版を記録する |
| 機密値の出力と対象CLIの実行 | 読み取り専用という前提を壊す | 模擬の秘密値・埋め込み指示・実行痕跡を残す模擬CLIで、外から観測できる検証を行う |
| 公開先・配布経路・ライセンス | 配布条件とモジュールの公開用識別子が未確定 | ローカルビルドまでとし、公開・署名・配布を開始する前に決める |

## 現在地

- 完了: M0〜M2。明示したファイルの実体解決と読取確認、共有リンク・別名の集約、直下のスキル列挙を追加した。本文の解析とCLIの候補検索は未実装として残している。
- 実装時の検証: Go 1.27.3・Windows/amd64、`GOCACHE=.cache/go-build`で必須の書式・モジュール整合性・静的検査・テスト・ビルド・起動が成功した。一時ディレクトリ内でシンボリックリンクの連鎖、リンク切れ・自己循環・相互循環、ハードリンク、ジャンクション、相対・絶対パス、空白・日本語、通常ファイル以外、不正なテキスト、直下だけの列挙とスキルの別名を確認した。Windowsの共有を拒むファイルハンドルで、通常ファイルとリンク先の読取不能を確認した。リンク作成不可によるスキップはなかった。
- M2の受入確認: ビルドした実行ファイルを模擬データで動かし、正常な別名の集約、切れたリンク・循環、正常な親リンク配下でのファイル不在、直下のスキルだけの列挙、通常表示・JSON・分類別件数・終了コード`2`、指定順と再指定に依存しない出力を確認した。エラー3件・判定不能6件の結果と終了コードが一致した。ファイルのSHA-256、更新日時、属性、リンク先、ディレクトリ構成は前後で一致し、模擬CLIの起動痕跡と模擬秘密値の出力はなかった。実装時の自己検証と実行ファイルでの受入確認を分けた。変更文書のローカルリンクは`lychee --offline`でエラーなし。
- 独立確認: 読み取り専用の補助担当が差分を確認し、ドライブ文字に割り当てたネットワーク共有を開く漏れを指摘した。`GetDriveTypeW`による事前判定を追加し、修正後の限定確認で指摘の解消を確認した。実際のネットワークドライブへの割当や接続は行わず、Windows APIの種別に対する判定をテストした。独立確認は静的な差分確認で、実行確認ではない。
- 検証対象: 基準コミット`4845d0f`にM2の変更を加えたCLI版`0.1.0`。受入確認した実行ファイルのSHA-256は`02b94c485ad0581811c07e73f7645be94219f9d846c8002f7538eb2dffb1d9c9`。正本と`bin/rulecheck.exe --version`の一致を確認した。
- 未完了: M3・M4。要件7節の4は相対参照の解釈が未実装で、実体パスと記述元の確定まで確認した。Markdown・YAML・CLIの検査本体と、解析後の安全上の境界を含む全体の受入確認は未実施。
- 次: M3。Markdown・YAMLの解析方式を確定し、参照・メタデータ・明示したCLI候補の検査を実装する。
- 版管理: CLIは`0.1.0`から`0.1.0`へ据え置き。初版の検査機能が未完成で未配布のため、READMEの規則を適用した。JSON形式も未配布の初回番号`1`を維持した。要件定義書は変更していない。
