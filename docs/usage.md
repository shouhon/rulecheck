# 使い方の詳細

```powershell
rulecheck scan --rules ./AGENTS.md --skills ./skills --command rg --json
$LASTEXITCODE
```

`--rules`・`--skills`・`--skill`・`--command`は繰り返して指定でき、少なくとも1つの対象が必要です。`--rules=./AGENTS.md`のような指定にも対応します。空白を含むパスは引用符で囲み、`-`で始まる値は`=`で指定してください。`--command`にはパスではなく、`PATH`から探す名前を指定します。

通常の結果は標準出力へ日本語で表示します。`--json`指定時は標準出力へJSONオブジェクト1件だけを出します。不正引数は終了コード`64`となり、標準エラーへ診断を出します。この場合も`--json`があれば、標準出力には`status: invalid_arguments`のJSONを返します。指定順を変えても結果の順序は一定です。同じ種類で同じ実体を指定した対象はまとめ、相対・絶対パス、シンボリックリンク、ハードリンク、ジャンクションによる別名と参照関係を残します。

## 参照の検査件数を確認する

参照検査の件数は通常表示の`参照:`行と、JSONの`reference_counts`で確認できます。`--summary`・`--quiet`でも保持します。例えば、存在するファイルへのリンク1件とインラインコード1件を含む文書では、次の値になります。

```json
{
  "reference_counts": {"checked": 1, "passed": 1, "error": 0, "unknown": 0, "skipped": 1}
}
```

`checked`は`passed + error + unknown`と一致します。同じ参照先へのリンクも出現ごとに数え、記述元の同一実体への別名は集約します。`skipped`はコードブロックなどの対象外の診断件数で、ローカルパスに付く見出しの省略も含みます。[件数の定義](requirements.md#参照検査の件数)を参照してください。

参照0件なら`checked: 0`となり、検査した参照がすべて正常なら`checked`と`passed`が同じ正の数になります。本文の読取不能などで検査できなかった対象は件数から推測できないため、`coverage.references`も確認してください。

## 対象外の診断を件数にまとめる

外部参照、見出し、コード中の例が多い場合は`--summary`を付けます。通常表示でも利用できます。

```powershell
rulecheck scan --rules ./AGENTS.md --json --summary

# 対象外の記述元・行番号などの詳細も取得する
rulecheck scan --rules ./AGENTS.md --json
```

要約時は`results[].findings`から`skipped`だけを除き、全対象を通じた`code`別件数を`skipped_summary`へ出します。例えば外部参照700件、見出し1件、コード中の例2件なら、次の配列になります。

```json
[
  {"code": "reference_code_skipped", "count": 2},
  {"code": "reference_external_skipped", "count": 700},
  {"code": "reference_fragment_skipped", "count": 1}
]
```

配列は`code`の昇順です。対象外が0件の場合と通常の詳細出力では`skipped_summary`を省きます。要約しても`counts.skipped`は省略前の総件数（この例では703件）を保ちます。エラー・注意・判定不能の詳細、対象の識別情報、`coverage`・`status`・終了コードは変わりません。対象外の詳細だけだった`findings`は空配列になります。

## 正常項目を省略する

正常なスキルが多い場合は`--quiet`を付けます。対象外の診断を種類別件数にまとめ、エラー・注意・判定不能のない対象のパス・実体・別名を省略します。

```powershell
rulecheck scan --skills ./skills --quiet
rulecheck scan --skills ./skills --json --quiet
```

正常な50スキルとその親を検査し、本文に参照もコード中の例もない場合の通常表示は次の4行です。

```text
検査完了
検査対象: 51件
参照: 検査対象 0 / 成功 0 / エラー 0 / 判定不能 0 / 対象外 0
件数: エラー 0 / 注意 0 / 判定不能 0 / 対象外 0
```

検査対象数は、同じ種類の同一実体を集約した後、省略する前の件数です。指定した親ディレクトリも含みます。JSONでは`target_count`にこの件数を残し、`results`には問題のある対象だけを残します。すべて正常なら`results`は空配列です。対象外の種類別件数は`skipped_summary`に残り、問題の詳細と`coverage`・`counts`・`status`・終了コードは変わりません。`--summary`との併用も可能です。すべての詳細を取得するには両方の指定を外してください。

## 1件のスキルを検査する

親ディレクトリ全体を検査する必要がない場合は`--skill`でスキルディレクトリを指定します。

```powershell
rulecheck scan --skill ./skills/new-skill --quiet
rulecheck scan --skill ./skills/first --skill ./skills/second --json
```

指定先の`SKILL.md`の基本項目・名前・ローカル参照を確認し、親・兄弟・入れ子のスキルは列挙しません。`--rules ./skills/new-skill/SKILL.md`では本文の参照だけを検査するため、スキルの構成確認には`--skill`を使ってください。指定先や`SKILL.md`の不存在、種類の誤り、リンク切れはエラー、読取不能は判定不能として残します。

`--skills`などほかの対象指定と併用でき、同じ実体への指定が重なっても1件にまとめます。名前の重複は今回選んだスキル間でだけ比較します。1件だけの検査から、選ばなかったスキルとの重複は判定しません。

## 検査範囲と判定

指定ファイルの不存在、リンク切れ・循環、対象の種類の誤りはエラー、読取不能は判定不能として区別します。本文はUTF-8で読み、解釈できない文字コードやNULを含むものは判定不能とします。`--skills`は親の直下にある各ディレクトリの`SKILL.md`だけを列挙し、補助ディレクトリの中へ再帰しません。`--skill`は明示した1件の`SKILL.md`だけを検査します。未対応のWindows再解析ポイントは、`SKILL.md`がない場合と区別して判定不能として残します。UNCパス、ネットワークドライブ、デバイス名などは開かず判定不能とします。出力項目と検査範囲の表現は[構成と実装方針](architecture.md#結果の形式)を参照してください。

MarkdownはCommonMarkの通常・参照形式・画像のリンクを対象とします。相対参照は記述元の実体ディレクトリを基準にし、参照先の存在と種類だけを確認します。空白を含む参照は`[説明](<空白 日本語.md>)`または`%20`を使い、Windowsの絶対パスも指定できます。外部URL、見出し、コード中の例は対象外として残します。未定義の参照形式、二重角括弧、参照属性を含むHTML、`file:` URIなどの未対応表記は判定不能です。通常表示とJSONには、異常の記述元・分かる場合の行番号・関係するパスを残し、本文や外部URL自体は転載しません。

スキルは先頭の`---`で囲んだYAMLを解析し、`name`・`description`の欠落、空文字列、型の誤り、不正な構文をエラーにします。引用文字列、複数行文字列、別名、マージ、追加項目に対応します。同じ実体への別名をまとめ、異なる実体での同名と、実体ディレクトリ名との差異を注意として表示します。YAMLの値自体は診断へ転載しません。

`--command`は現在の`PATH`を指定順に調べ、最初に確認できた通常ファイルの候補と共有リンクの実体を表示します。Windowsでは`PATHEXT`の順序を使い、空なら`.COM;.EXE;.BAT;.CMD`を使います。拡張子を含む名前は、その名前も先に確認します。作業ディレクトリは暗黙に追加せず、`PATH`に明記された相対ディレクトリだけを作業ディレクトリ基準で解決します。ネットワーク上や確認できない場所を除いて候補が見つかれば存在確認を完了し、候補がなく確認できない場所が残れば、不足と断定せず判定不能とします。候補の本文は読まず、起動・認証・実行権限・実行ポリシーは確認しません。PowerShellの関数とエイリアスも対象外です。
